## Подготовленные измерения

- Native UDP datagram sample: T = вызов отправки, R = получение в очередь,
  D = чтение игрой. Одинаковый payload имеет один FNV64, даже после framing/crypto;
  записываются размер, пара vport, epoch microseconds, время в очереди.
  Payload/ключи/пароли не записываются. Это не распознавание конкретного попадания.
- Storage ограничено 1024 событиями в пятесекундной пачке, 65536 записями на
  transport. Пропуски диагностики считаются отдельно и не меняют игровые пакеты.
- Для TCP-over-UDP выводятся state/retransmissions/unread: пропуск сегмента может
  задержать поток; нельзя предполагать, что все боевые данные — UDP snapshots.
- Форматирование ограничено размером пачки. Запись журнала перенесена за mutex
  транспорта: файловый I/O не держит общий lock SendTo/RecvFrom.
- Windows sink читает процессное окружение через Win32 и поддерживает
  BB_GPU_USER_DIR наряду с BB_USER_DIR. Регрессионный тест проверяет Unicode path,
  отсутствие BB_USER_DIR и изменения окружения после инициализации CRT.
  Старый sink в последнем прогоне не создал файл; конкретная причина неизвестна.
- HP/AI/death ownership, native очереди/порядок/потери, частоты отправки, сервер,
  мод чаш и сейвы не меняются. Это измерительная сборка, не «ускорение урона».
